# 企业 AI 模型访问控制与调用安全规范（样例）

## 控制目标

企业部署 AI 模型后，应建立访问控制和调用安全机制，确保只有授权用户和系统可以调用模型接口，调用行为可追溯，异常调用可及时发现和阻断。

## 身份认证

模型接口应要求身份认证，支持 API Key、OAuth 2.0、mTLS 或企业 SSO 集成。认证凭据应定期轮换，泄露时应立即吊销。服务间调用应使用独立的服务账号，不得复用个人凭据。

## 权限分级

模型调用权限应分为管理员、开发者、普通用户和只读用户。管理员可以修改模型配置和访问策略，开发者可以上传文档和创建评测集，普通用户可以提问和查看回答，只读用户仅可查看公开知识库内容。

## 调用限流

模型接口应配置调用频率限制，包括每用户每分钟请求数、每用户每日请求数、全局并发请求数和单次请求 token 上限。限流触发时应返回标准错误码和限流解除时间，不得返回模型内部错误信息。

## 输入过滤

模型接口应对输入内容进行过滤，检测并拒绝包含注入攻击、越狱指令、敏感数据导出尝试和恶意代码执行意图的请求。输入过滤规则应定期更新，过滤日志应留存审计。

## 输出审查

模型输出应经过内容安全审查，检测是否包含敏感信息泄露、有害内容、幻觉事实和越权信息。高风险输出应触发人工审核流程，审核完成前不得返回给用户。

## 审计日志

模型调用审计日志应记录请求身份、请求时间、输入摘要、输出摘要、使用的 token 数、响应时间、命中权限、触发的过滤规则和异常标记。审计日志应至少保留一百八十天，支持按用户、时间和事件类型检索。

## 异常检测

模型调用异常检测应覆盖请求频率突增、异常时间段调用、非常规地理位置访问、输入模式异常、输出内容异常和凭据复用告警。异常事件应自动通知安全负责人并触发临时限流或封禁。
