# 数据出境安全评估申报流程评测摘要（样例）

参考来源：国家互联网信息办公室《数据出境安全评估申报指南（第一版）》发布信息。本文档为 KnowledgePilot 评测用摘要，不替代正式申报指南。

## 1. 适用情形

数据处理者因业务需要向境外提供数据，且符合数据出境安全评估适用情形时，应按照数据出境安全评估要求进行申报。常见场景包括跨国集团统一运营、境外客户服务、海外供应链协同、全球研发支持、跨境售后诊断、境外系统集中存储和境外合作伙伴处理数据。

企业判断是否需要申报时，应同时关注数据类型、数据规模、是否涉及重要数据、是否涉及个人信息、接收方所在国家或地区、数据处理目的、出境方式和后续再转移安排。仅凭“系统部署在境外”或“数据通过接口同步”无法替代完整判断。

## 2. 申报材料

申报材料通常包括申报书、自评估报告、与境外接收方订立的法律文件、数据处理活动说明、数据出境场景说明、数据清单、安全措施说明和其他主管部门要求的材料。材料应能够说明谁提供数据、向谁提供、提供什么数据、为什么提供、如何传输、保存多久、如何保护、如何退出。

自评估报告应覆盖出境目的合法性、正当性和必要性，数据规模、范围、种类和敏感程度，境外接收方的数据保护能力，数据出境和再转移风险，个人信息权益影响，重要数据安全影响，以及合同或其他法律文件中约定的责任义务。

## 3. 自评估重点

自评估应先界定业务场景和数据流向。企业需要列出来源系统、目标系统、字段范围、接口方式、传输频率、保存位置、访问角色、境外接收方、再转移对象和删除机制。涉及多个业务场景时，应分别评估，不宜用一个概括性说明覆盖所有数据流。

自评估还需要说明安全控制措施。传输环节应说明加密、鉴权、完整性校验和通道控制；存储环节应说明访问控制、加密、隔离和备份；使用环节应说明最小权限、日志审计、异常监测和人员管理；退出环节应说明到期删除、授权撤回、合同终止和应急处置。

## 4. 合同和接收方责任

企业与境外接收方的法律文件应明确数据处理目的、处理方式、数据范围、保存期限、存储地点、安全保护措施、再转移限制、个人权益保障、事件通知、审计配合、违约责任和退出删除要求。接收方不得超出约定目的处理数据，也不得在未满足约定条件时再转移给其他组织或个人。

接收方安全能力评估应关注其组织管理、技术保护、访问控制、日志审计、事件响应、人员管理、分包管理和历史安全事件。对于高敏感数据或重要数据，企业应要求接收方提供更强的证明材料，例如安全认证、第三方审计报告、渗透测试结果或数据保护制度。

## 5. 申报和整改流程

企业准备申报前，应先完成内部自评估和材料一致性检查。材料提交后，主管部门可能要求补充说明、修改材料或完善安全措施。企业应建立问题清单，明确责任人、补充材料、整改措施和完成期限。涉及数据范围、接收方、目的或安全措施发生重大变化时，需要重新评估并按要求处理。

申报通过后，企业仍需持续管理数据出境活动。持续管理包括定期复核数据范围、检查接收方履约情况、监测异常访问、处理个人权益请求、保存审计证据和开展应急演练。出现安全事件、接收方违反约定、境外环境变化或数据处理目的变化时，应及时启动风险处置。

## 6. 企业落地建议

企业应建立数据出境台账，记录业务场景、数据类型、字段清单、出境方式、接收方、合同编号、安全措施、申报状态和复核日期。台账应与数据目录、接口清单、合同管理和权限系统联动，避免申报材料与实际系统配置不一致。

对于跨境数据活动较多的企业，应建立前置评审机制。业务部门提出出境需求时，数据所有者、安全、法务、合规和系统负责人共同确认必要性、最小范围和安全措施。高风险场景应先采用脱敏、匿名化、聚合统计、本地计算或境内替代方案，减少明文数据出境。
