# 企业安全运营中心（SOC）管理规范（样例）

## 文档信息
- 文档编号：SEC-SOC-001
- 版本：1.0
- 适用范围：安全运营中心全体人员和关联团队

本文档是用于 KnowledgePilot 评测的中文企业级样本文档，描述一家企业安全运营中心的管理要求。

## 1. SOC 组织架构

### 1.1 团队组成
安全运营中心应配备以下角色：
- L1 分析师：负责告警初步分类、筛选和基础调查
- L2 分析师：负责深度威胁分析、事件确认和响应协调
- L3 专家：负责高级威胁猎捕、恶意代码分析和应急处置
- 威胁情报分析师：负责威胁情报收集、分析和分发
- 安全工程师：负责安全工具运维和检测规则维护

### 1.2 值班制度
SOC 应实施 7x24 小时值班制度。工作日白班至少配置 L1 分析师两名和 L2 分析师一名。夜班和节假日至少配置 L1 分析师一名，L2 分析师按需远程接入。值班人员应每季度轮换一次。

## 2. 告警管理

### 2.1 告警分级
安全告警应按以下标准分级：
- P1 紧急：确认的数据泄漏、勒索攻击、核心系统入侵，响应时间不超过十五分钟
- P2 高危：可疑的未授权访问、恶意代码检出、异常数据导出，响应时间不超过一小时
- P3 中危：策略违规、弱密码检测、异常登录行为，响应时间不超过四小时
- P4 低危：信息类告警、扫描行为、已知误报模式，响应时间不超过二十四小时

### 2.2 告警处理流程
告警处理应遵循以下流程：
- 接收和分类：自动接收并按规则预分类
- 初步研判：L1 分析师确认告警有效性和基本信息
- 深入分析：L2 分析师进行上下文关联和影响评估
- 响应处置：根据告警级别执行相应响应动作
- 闭环归档：记录处置过程和结论，更新检测规则

### 2.3 告警降噪
SOC 应持续优化告警质量：
- 每月分析告警误报率，优化检测规则
- 建立白名单机制，排除已确认的安全行为
- 关联多源告警，合并同一事件的重复告警
- 使用上下文信息丰富告警，提高研判效率

## 3. 威胁检测

### 3.1 检测数据源
SOC 应接入以下安全数据源：
- 网络流量数据：防火墙、IDS/IPS、WAF、网络流量分析
- 终端数据：EDR、终端防护、系统日志
- 身份数据：认证日志、权限变更、SSO 日志
- 应用数据：应用日志、API 网关日志、数据库审计
- 云安全数据：云平台安全日志、容器安全、配置审计

### 3.2 检测规则管理
检测规则应覆盖以下威胁场景：
- 已知威胁：基于 IOC 匹配和特征签名检测
- 行为异常：基于用户和实体行为分析（UEBA）检测
- 策略违规：基于安全策略规则检测合规偏差
- 数据泄漏：基于 DLP 规则检测敏感数据外传

## 4. 威胁情报

### 4.1 情报来源
SOC 应订阅以下威胁情报来源：
- 行业共享情报：行业 CERT 和 ISAC 发布的威胁通报
- 商业情报服务：专业威胁情报厂商提供的 IOC 和 TTP
- 开源情报：安全社区、漏洞公告和研究报告
- 内部情报：从安全事件中提取的内部 IOC 和攻击特征

### 4.2 情报应用
威胁情报应应用于以下场景：
- 检测规则更新：将新 IOC 转化为检测规则
- 事件关联分析：使用情报丰富事件上下文
- 风险评估：基于威胁态势调整安全防护重点
- 主动猎捕：基于情报线索开展威胁猎捕

## 5. 安全度量

### 5.1 运营指标
SOC 应监控以下运营指标：
- 平均检测时间（MTTD）：从威胁发生到检出的平均时间
- 平均响应时间（MTTR）：从检出到遏制的平均时间
- 告警处理率：在 SLA 内完成处理的告警比例
- 事件升级率：L1 升级到 L2 的事件比例
- 误报率：确认为误报的告警占总告警比例

### 5.2 报告机制
SOC 应产出以下报告：
- 每日安全态势摘要，包含告警统计和重要事件
- 每周威胁趋势分析，包含新增威胁和防护建议
- 每月安全运营报告，包含关键指标和改进计划
- 重大事件专项报告，包含事件详情和复盘结论
