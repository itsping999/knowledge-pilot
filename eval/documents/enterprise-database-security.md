# 企业数据库安全管理规范

## 文档信息
- 文档编号：SEC-DB-001
- 版本：1.0
- 适用范围：企业所有关系型数据库、NoSQL 数据库和数据仓库

## 1. 数据库访问控制

### 1.1 账户管理
数据库应实施最小权限原则，为不同应用和人员创建独立的数据库账户。禁止使用数据库默认管理员账户（如 sa、root）运行业务应用。数据库管理员账户应与个人身份绑定，禁止共享账户。离职人员的数据库账户应在离职当天禁用，三十天后删除。

### 1.2 权限分层
数据库权限应分为以下层级：
- 只读权限：允许 SELECT 查询，适用于数据分析和报表用户
- 读写权限：允许 SELECT、INSERT、UPDATE 和 DELETE，适用于业务应用
- 结构管理权限：允许 CREATE、ALTER 和 DROP，适用于开发和 DBA
- 管理员权限：允许所有操作，仅授予数据库管理员

### 1.3 访问审计
数据库应开启操作审计功能，记录以下操作：
- 登录和登出事件（成功和失败）
- DDL 操作（表结构变更）
- DML 操作（数据查询、修改和删除）
- 权限授予和回收操作
- 敏感表和字段的访问操作

审计日志应保留一百八十天以上，关键操作的审计日志应实时告警。

## 2. 数据加密

### 2.1 传输加密
数据库客户端连接应使用 TLS 加密，禁用不加密的数据库连接。数据库主从复制应使用加密通道。跨数据中心的数据库同步应通过 VPN 或专线传输。

### 2.2 存储加密
包含敏感数据的数据库应启用透明数据加密（TDE）。数据库备份文件应加密存储。加密密钥应通过密钥管理系统管理，密钥轮换周期不超过三百六十五天。数据库字段级加密应使用 AES-256 算法，加密密钥应与数据库分开存储。

## 3. 数据库安全配置

### 3.1 安全基线
数据库部署应遵循以下安全基线：
- 修改默认端口，禁用不必要的网络监听
- 删除或禁用默认测试数据库和示例数据
- 禁用不必要的存储过程和扩展功能
- 设置连接超时时间和最大连接数限制
- 配置登录失败锁定策略（连续五次失败锁定三十分钟）
- 启用密码复杂度策略和密码过期策略

### 3.2 补丁管理
数据库安全补丁应在发布后七天内完成评估，严重漏洞补丁应在十四天内完成更新。补丁更新前应在测试环境完成兼容性测试。补丁更新应安排在业务低峰期，并提前制定回滚方案。

## 4. 数据库备份与恢复

### 4.1 备份策略
数据库应实施以下备份策略：
- 每日增量备份，备份窗口安排在业务低峰期
- 每周全量备份，保留最近四个全量备份
- 关键业务数据库应配置实时复制（主从或主主）
- 备份数据应存储在与源数据库不同的物理位置

### 4.2 恢复测试
数据库恢复演练应每月执行一次，验证备份数据的完整性和恢复时间。恢复演练的目标恢复时间（RTO）和恢复点目标（RPO）应满足业务连续性要求。恢复演练结果应记录并报告给数据安全负责人。

## 5. 数据库安全监控

### 5.1 异常行为检测
数据库安全监控应检测以下异常行为：
- 非工作时间的大量数据查询或导出
- 单个账户短时间内执行大量 DDL 操作
- 异常来源 IP 的数据库连接
- 敏感表的大范围扫描操作
- SQL 注入攻击特征
- 数据库权限异常提升

### 5.2 性能与安全告警
数据库监控应设置以下告警规则：
- 数据库连接数超过阈值（最大连接数的百分之八十）
- 慢查询数量异常增加
- 死锁频繁发生
- 磁盘空间不足（剩余空间低于百分之二十）
- 数据库主从复制延迟超过阈值

告警应通过短信、邮件和即时通讯工具发送给数据库管理员和安全团队。
