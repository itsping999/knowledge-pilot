# 企业身份与访问管理规范（样例）

## 文档信息
- 文档编号：SEC-IAM-001
- 版本：1.0
- 适用范围：全体员工、外包人员、合作伙伴账号管理

本文档是用于 KnowledgePilot 评测的中文企业级样本文档，描述一家企业在身份与访问管理方面的制度要求。

## 1. 账号生命周期管理

### 1.1 账号开通
新员工入职时应由直属上级提交账号开通申请，经人力资源部门确认后由 IT 部门创建账号。账号命名应遵循统一规范，包含工号或姓名缩写，不得使用个人邮箱或昵称。外包人员和合作伙伴账号应标注来源和有效期，最长不超过合同期限。

### 1.2 账号变更
员工岗位变更时应在五个工作日内调整权限，移除与新岗位无关的权限。部门调动应重新评估并签署权限确认表。权限变更应经直属上级和目标系统管理员双重审批。

### 1.3 账号注销
员工离职时应在离职当日禁用账号，三十个自然日后删除。外包人员合同到期时应同步注销所有系统访问权限。长期未使用的账号（超过九十天无登录记录）应自动禁用并通知管理员。

## 2. 访问控制策略

### 2.1 最小权限原则
所有系统访问权限应基于最小权限原则配置。默认情况下新用户不拥有任何系统权限，权限应通过审批流程逐项授予。权限授予应基于岗位职责而非个人需求。

### 2.2 基于角色的访问控制
企业应建立统一的角色体系，角色应按部门、职能和层级划分。每个角色的权限范围应明确定义并经安全团队审核。角色权限变更应经变更管理流程审批。

### 2.3 特权账号管理
系统管理员、数据库管理员和网络管理员等特权账号应实施以下管控：
- 特权账号应与个人日常工作账号分离
- 特权操作应通过堡垒机或特权访问管理平台执行
- 特权会话应全程录屏和日志记录
- 特权账号密码应由密码管理系统自动轮换
- 紧急特权使用应事后补录审批记录

## 3. 认证管理

### 3.1 认证方式
企业应根据系统敏感程度选择认证方式：
- 普通业务系统：用户名密码加设备绑定
- 敏感业务系统：双因素认证（密码加动态令牌）
- 核心系统：双因素认证加上下文验证（IP、设备、时间）
- 远程访问：VPN 加双因素认证

### 3.2 单点登录
企业应在主要业务系统间部署单点登录（SSO），使用 SAML 2.0 或 OpenID Connect 协议。SSO 会话有效期不超过八小时，敏感操作应重新认证。SSO 系统应支持强制下线和会话撤销。

## 4. 权限审计

### 4.1 定期审计
企业应每季度开展一次权限审计，检查以下内容：
- 离职人员账号是否已注销
- 岗位变更人员权限是否已调整
- 长期未使用账号是否已处理
- 特权账号使用是否合规
- 角色权限是否与岗位职责匹配

### 4.2 异常行为检测
身份管理系统应监控以下异常行为：
- 非工作时间的登录尝试
- 短时间内多次登录失败
- 同一账号在不同地理位置同时登录
- 权限提升操作未经过审批
- 大量数据导出操作

审计发现应生成告警并通知安全团队，高风险发现应在二十四小时内完成调查。
