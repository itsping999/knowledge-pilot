# 企业密码管理规范

## 文档信息
- 文档编号：SEC-PWD-001
- 版本：1.0
- 适用范围：全体员工、外包人员、合作伙伴

## 1. 密码复杂度要求

### 1.1 通用密码规则
企业所有系统账户密码应满足以下复杂度要求：
- 长度不少于十二个字符，特权账户不少于十六个字符
- 应包含大写字母、小写字母、数字和特殊字符中的至少三类
- 不得包含用户名、姓名拼音、生日或连续字符（如 123456、abcdef）
- 不得使用最近五次使用过的密码
- 密码中不得包含公司名称、产品名称或常见字典词汇

### 1.2 特殊系统密码规则
数据库管理员账户密码应不少于二十个字符，且每九十天强制更换。操作系统 root 或 Administrator 密码应不少于十六个字符，且每六十天强制更换。网络设备管理员密码应不少于十六个字符，且应通过带外通道分发。

## 2. 密码存储与传输安全

### 2.1 密码存储
密码应使用 bcrypt、scrypt 或 Argon2 等抗暴力破解算法进行哈希存储，不得使用 MD5 或 SHA-1 等弱哈希算法。每个密码应使用独立的随机盐值，盐值长度不少于十六字节。密码哈希值应存储在受保护的数据库表中，仅允许应用服务账号访问。

### 2.2 密码传输
密码在网络传输过程中应使用 TLS 1.2 及以上版本加密保护。登录接口应实施防暴力破解措施，包括账户锁定、验证码和请求频率限制。密码重置链接应设置有效期，不超过二十四小时，且使用后立即失效。

## 3. 多因素认证

### 3.1 强制多因素认证场景
以下场景应强制启用多因素认证：
- 远程访问企业内网（VPN、远程桌面）
- 访问生产环境服务器和数据库
- 管理员登录后台管理系统
- 访问敏感数据导出功能
- 财务系统和人力资源系统的关键操作
- 代码仓库的推送和合并操作

### 3.2 多因素认证方式
支持的多因素认证方式包括硬件安全密钥（FIDO2/WebAuthn）、TOTP 动态令牌（如 Google Authenticator）、短信验证码（仅作为备用方式）。优先使用硬件安全密钥，短信验证码仅在其他方式不可用时作为降级方案。

## 4. 特权账户密码管理

### 4.1 特权账户定义
特权账户包括系统管理员账户（root、Administrator）、数据库管理员账户（DBA）、网络设备管理员账户、云平台管理员账户、应用超级管理员账户和共享服务账号。

### 4.2 特权密码管理要求
特权密码应存储在企业级特权密码管理系统中。特权密码的使用应通过审批流程，记录使用人、使用时间、使用目的和操作内容。特权密码应定期自动轮换，核心系统每七天轮换一次，重要系统每三十天轮换一次。特权密码管理系统应具备高可用性，确保紧急情况下密码可正常获取。

## 5. 密码泄露检测与响应

### 5.1 泄露检测
企业应接入公开密码泄露数据库（如 Have I Been Pwned），定期检查企业域账号是否出现在泄露数据中。应监控暗网和数据交易市场，发现企业账号泄露后立即启动应急响应。

### 5.2 泄露响应
发现密码泄露后应在四小时内完成以下处置：强制受影响账户更换密码、检查账户近期登录记录和操作日志、评估泄露范围和影响程度、通知受影响用户并提供安全指导。对于批量泄露事件，应升级为安全事件并启动应急响应流程。

## 6. 密码策略执行与审计

### 6.1 策略执行
企业应通过统一身份认证平台强制执行密码策略，包括复杂度检查、历史密码比对和过期提醒。密码策略应覆盖所有接入统一认证的系统和应用。对于无法接入统一认证的遗留系统，应通过技术手段或管理流程确保密码策略得到执行。

### 6.2 审计要求
密码管理相关的审计日志应记录密码修改、密码重置、多因素认证设置变更、特权密码访问和密码策略变更。审计日志应保留一百八十天以上。密码管理策略应每年评审一次，根据安全威胁变化及时更新。
