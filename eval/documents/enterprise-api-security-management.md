# 企业 API 安全管理规范（样例）

## API 生命周期管理

企业应建立 API 全生命周期管理机制，覆盖 API 设计、开发、测试、发布、运行、变更和下线各阶段。每个 API 应登记在 API 管理平台，记录 API 名称、版本、负责人、业务用途、数据分类、安全等级和调用方信息。

## API 认证与授权

API 应要求调用方完成身份认证，认证方式包括 API Key、OAuth 2.0、JWT 和 mTLS。API 权限应按调用方角色和业务场景精细化配置，遵循最小权限原则。敏感 API 应增加二次认证或审批流程。

## API 传输安全

API 通信应使用 HTTPS，TLS 版本不得低于 1.2。涉及敏感数据的 API 应启用请求签名和防重放机制。API 响应头应配置安全策略，包括 HSTS、CSP、X-Content-Type-Options 和 X-Frame-Options。

## API 限流与防滥用

API 应配置限流策略，包括每秒请求数、每分钟请求数、每日请求数和并发连接数。限流粒度应支持按用户、按 IP 和按 API 维度。触发限流时应返回标准 429 响应，包含重试时间建议。

## API 输入校验

API 应对所有输入参数进行校验，包括参数类型、长度、格式、范围和业务规则。应防范 SQL 注入、XSS、XXE、SSRF 和参数篡改攻击。上传接口应校验文件类型、大小和内容安全。

## API 监控与告警

API 监控应覆盖响应时间、错误率、调用量、异常模式和安全事件。应配置告警规则，当响应时间超过阈值、错误率突增、检测到扫描行为或异常调用模式时触发告警。告警应通知 API 负责人和安全团队。

## API 下线管理

API 下线应提前通知调用方，设置过渡期，过渡期内应保持兼容性。下线后应保留 API 文档和审计日志不少于一百八十天。已下线的 API 端点应返回明确的错误响应，不得暴露内部接口信息。
