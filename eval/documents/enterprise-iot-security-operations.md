# 星河制造集团物联网安全运营规范（样例）

## 1. 总则

为加强集团物联网（IoT）设备和系统的安全管理，防范物联网安全风险，保障工业生产安全和数据安全，依据《网络安全法》《数据安全法》和工业互联网安全相关标准，结合集团智能制造建设实际，制定本规范。本规范适用于集团所有物联网设备、工业控制系统和智能制造平台的安全管理。

## 2. 物联网资产分类

### 2.1 设备分类

物联网设备按功能分为以下类别：

1. 工业控制设备：PLC（可编程逻辑控制器）、DCS（分布式控制系统）、SCADA（数据采集与监控系统）、RTU（远程终端单元）和 HMI（人机界面）。
2. 传感设备：温度传感器、压力传感器、流量计、振动传感器和环境监测传感器。
3. 网络设备：工业交换机、工业无线 AP、物联网网关和边缘计算节点。
4. 视觉设备：工业相机、视频监控摄像头和机器视觉系统。
5. 执行设备：工业机器人、AGV（自动导引车）、数控机床和 3D 打印机。

### 2.2 网络分区

物联网网络应按照 Purdue 模型进行分区：

1. Level 0-1（现场层）：传感器、执行器和控制设备。
2. Level 2（控制层）：SCADA 系统、HMI 和历史数据库。
3. Level 3（操作层）：MES 系统、数据采集服务器和工程工作站。
4. Level 3.5（DMZ）：IT/OT 边界隔离区。
5. Level 4-5（企业层）：ERP 系统、办公网络和互联网接入。

### 2.3 资产登记

所有物联网资产应在 CMDB 中登记，记录以下信息：

1. 设备标识：设备名称、型号、序列号和 MAC 地址。
2. 网络信息：IP 地址、VLAN 和网络分区。
3. 软件信息：固件版本、操作系统和应用软件。
4. 责任信息：设备负责人、维护团队和联系方式。
5. 安全信息：安全等级、认证状态和漏洞情况。

## 3. 设备安全管理

### 3.1 设备准入

物联网设备接入网络应满足以下准入条件：

1. 设备认证：设备应通过安全认证，具有可信的设备标识。
2. 固件验证：设备固件应经过完整性验证，未被篡改。
3. 安全配置：设备应配置安全基线，禁用不必要的服务和端口。
4. 网络授权：设备应获得网络接入授权，分配到正确的 VLAN。

### 3.2 设备身份管理

物联网设备身份管理应遵循以下原则：

1. 唯一标识：每个设备应具有唯一的身份标识。
2. 证书管理：设备应使用数字证书进行身份认证。
3. 密钥轮换：设备密钥应定期轮换，周期不超过一年。
4. 设备注销：退役设备应及时注销身份和回收证书。

### 3.3 设备固件管理

物联网设备固件管理应遵循以下规范：

1. 固件来源：固件应来自可信的厂商或内部开发团队。
2. 固件验证：固件更新前应进行完整性验证和安全扫描。
3. 固件更新：固件更新应通过安全通道分发，支持回滚机制。
4. 固件版本：应维护固件版本清单，及时更新已知漏洞的固件。

## 4. 网络安全

### 4.1 网络隔离

物联网网络应实施以下隔离措施：

1. IT/OT 隔离：工业控制网络与办公网络应物理隔离或通过防火墙逻辑隔离。
2. 区域隔离：不同生产区域的控制网络应相互隔离。
3. 纵向隔离：Purdue 模型各层级之间应通过防火墙和数据二极管隔离。
4. 横向隔离：同一层级的不同系统应通过 VLAN 隔离。

### 4.2 访问控制

物联网网络访问应实施以下控制：

1. 远程访问：远程访问应通过 VPN 和堡垒机，实施双因素认证。
2. 现场访问：现场设备维护应通过专用维护终端，记录操作日志。
3. 无线访问：工业无线网络应使用 WPA3 加密，实施 MAC 地址过滤。
4. 互访控制：不同安全域之间的互访应经过审批和记录。

### 4.3 流量监控

物联网网络流量应实施以下监控：

1. 基线建立：建立正常流量基线，检测异常流量。
2. 协议检测：检测非标准协议和异常通信模式。
3. 横向移动：检测设备之间的异常横向通信。
4. 外联检测：检测设备的异常外部连接。

## 5. 数据安全

### 5.1 数据采集安全

物联网数据采集应遵循以下安全要求：

1. 采集授权：数据采集应经过授权，明确采集范围和目的。
2. 采集完整性：确保采集数据的完整性和准确性。
3. 采集频率：根据业务需求确定采集频率，避免过度采集。
4. 边缘处理：敏感数据应在边缘侧进行预处理，减少原始数据传输。

### 5.2 数据传输安全

物联网数据传输应实施以下安全措施：

1. 加密传输：数据传输应使用 TLS 1.2 及以上协议加密。
2. 完整性校验：数据传输应实施完整性校验，防止篡改。
3. 协议安全：优先使用安全的工业协议（如 OPC UA），对不安全协议进行封装。
4. 带宽管理：合理分配网络带宽，确保关键数据优先传输。

### 5.3 数据存储安全

物联网数据存储应遵循以下要求：

1. 分级存储：根据数据重要性和使用频率选择存储方式。
2. 加密存储：敏感数据应加密存储。
3. 访问控制：数据访问应实施权限控制。
4. 保留期限：根据业务需求和合规要求确定数据保留期限。

## 6. 漏洞管理

### 6.1 漏洞发现

物联网漏洞发现应采用以下方式：

1. 厂商公告：跟踪设备厂商的安全公告和补丁信息。
2. 漏洞扫描：定期对物联网设备进行漏洞扫描。
3. 渗透测试：每年对关键物联网系统进行渗透测试。
4. 威胁情报：订阅工业控制系统相关的威胁情报。

### 6.2 漏洞评估

发现漏洞后应进行以下评估：

1. 影响评估：评估漏洞对生产安全和数据安全的影响。
2. 可利用性评估：评估漏洞被利用的难度和可能性。
3. 修复评估：评估修复方案的可行性和风险。
4. 优先级排序：根据影响和可利用性确定修复优先级。

### 6.3 漏洞修复

漏洞修复应遵循以下流程：

1. 修复方案：制定修复方案，包括补丁更新、配置调整或临时缓解。
2. 测试验证：在测试环境中验证修复方案，确保不影响生产。
3. 变更审批：通过变更管理流程审批修复方案。
4. 实施修复：在维护窗口期内实施修复。
5. 效果验证：验证修复效果，确认漏洞已被消除。

## 7. 安全监控与事件响应

### 7.1 安全监控

物联网安全监控应覆盖以下方面：

1. 设备状态监控：监控设备在线状态、运行状态和资源使用情况。
2. 网络流量监控：监控网络流量异常和通信模式变化。
3. 安全事件监控：监控安全告警和异常行为。
4. 配置变更监控：监控设备配置变更和固件更新。

### 7.2 事件响应

物联网安全事件响应应遵循以下流程：

1. 事件检测：通过监控系统或人工巡检发现安全事件。
2. 事件评估：评估事件的影响范围和严重程度。
3. 隔离处置：将受影响的设备从网络中隔离。
4. 根因分析：分析事件的根本原因。
5. 恢复重建：修复漏洞，恢复设备和系统。
6. 经验总结：总结事件处理经验，更新安全策略。

### 7.3 应急预案

物联网安全应急预案应包括：

1. 勒索软件攻击：工业控制系统感染勒索软件的应急响应。
2. 设备劫持：物联网设备被劫持的应急响应。
3. 数据泄露：工业数据泄露的应急响应。
4. 供应链攻击：设备固件被植入后门的应急响应。

## 8. 合规与审计

### 8.1 合规要求

物联网安全管理应满足以下合规要求：

1. 网络安全法：落实网络安全等级保护制度。
2. 数据安全法：保护工业数据的安全。
3. 关键信息基础设施保护：关键基础设施应满足更高的安全要求。
4. 工业互联网安全：满足工业互联网企业网络安全分类分级管理要求。

### 8.2 安全审计

物联网安全审计应定期进行：

1. 季度审计：每季度对物联网安全策略执行情况进行审计。
2. 年度评估：每年对物联网安全管理体系进行全面评估。
3. 专项审计：在安全事件后或重大变更后进行专项审计。

## 9. 培训与意识

### 9.1 培训计划

物联网安全培训应包括：

1. OT 安全培训：针对运维人员的工业控制系统安全培训。
2. 设备安全培训：针对设备管理人员的物联网设备安全培训。
3. 应急响应培训：针对安全团队的物联网安全事件响应培训。
4. 安全意识培训：针对全体员工的物联网安全意识培训。

## 10. 附则

本规范由信息安全部和制造工程部共同负责解释和修订，自发布之日起施行。
