# 企业知识库 Embedding 模型治理规范（样例）

## 管理目标

企业知识库的 embedding 模型用于将文档和问题转化为向量，是检索质量、权限隔离、引用准确性和低置信判断的基础能力。embedding 模型不得与通用对话模型混用，生成模型只能用于回答生成、查询规划或 Agentic 编排。

## 选型检查

企业选择 embedding 模型需要检查语义检索效果、中文行业术语覆盖、向量维度稳定性、批量嵌入吞吐、离线部署能力、许可证和商用授权、模型版本可追溯性、与现有索引兼容性、资源占用、冷启动时间、隐私边界和故障降级方式。

## 配置规则

embedding 配置应使用独立的模型名称、独立的服务地址和独立的调用路径。知识库配置中，`KNOWLEDGE_PILOT_EMBEDDING_MODEL` 只能填写 embedding 模型，例如 qwen3-embedding、bge-m3、nomic-embed-text 或 mxbai-embed-large。通用对话模型应配置在 `KNOWLEDGE_PILOT_LLM_MODEL`，用于可选生成器或查询规划器。

## 变更发布

embedding 模型变更发布流程包括第一步在灰度环境导入代表性语料，第二步重建全部文档索引，第三步运行标准评测集和业务高频问题集，第四步对比正确来源命中率、引用可用率、低置信率和检索延迟，第五步完成权限和审计抽检，第六步输出变更报告并保留旧索引回滚方案，第七步在正式环境分批切换。

## 运行监控

embedding 服务监控应覆盖请求成功率、向量维度、平均延迟、P95 延迟、错误码、模型版本、索引任务积压、重试次数和模型不可用时长。当 embedding 服务不可用时，应暂停新文档接入和重建索引，保留已构建索引的问答服务。
